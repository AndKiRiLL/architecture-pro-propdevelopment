# Требования к внешним интеграциям (Умный дом)

## 1. Общие требования

| № | Требование | Обоснование |
|---|------------|-------------|
| 1.1 | Взаимодействие с партнёром через выделенный сервис-адаптер `smart-home-integration-app` | Изоляция интеграций |
| 1.2 | Все запросы логируются (user_id, action, result) | Аудит, 152-ФЗ |
| 1.3 | Передаём только внутренний ID пользователя | Минимизация ПДн |
| 1.4 | Биометрические шаблоны хранятся у партнёра | Снижение ответственности по 152-ФЗ |
| 1.5 | Все данные в транзите шифруются TLS 1.3 | PCI DSS, 152-ФЗ |
| 1.6 | Запросы подписываются HMAC-SHA256 | Защита от replay-атак |
| 1.7 | В логах нет биометрии и ПДн | 152-ФЗ |
| 1.8 | Партнёр не имеет доступа к БД | Только через API |
| 1.9 | Интеграция проходит пентест | Проблемы с API партнёров в прошлом |

---

## 2. Аутентификация и авторизация

### 2.1. Пользователь

| № | Требование | Механизм |
|---|------------|----------|
| 2.1.1 | Аутентификация через существующий `auth-service` (Keycloak) | Единый вход |
| 2.1.2 | Пользователь получает JWT-токен | Стандарт REST API |
| 2.1.3 | API Gateway валидирует JWT | Проверка на входе |
| 2.1.4 | В сервис передаётся `user_id` из JWT | Исключение подделки |

### 2.2. Сервис -> Партнёр

| № | Требование | Механизм |
|---|------------|----------|
| 2.2.1 | Аутентификация сервиса перед партнёром | OAuth 2.0 Client Credentials |
| 2.2.2 | Каждый запрос с JWT-токеном | Защита от подделки |
| 2.2.3 | TTL токена = 1 час | Снижение риска компрометации |
| 2.2.4 | Шифрование канала | mTLS (TLS 1.3) |
| 2.2.5 | Секреты в HashiCorp Vault | Безопасное хранение |

### 2.3. Права доступа

| № | Требование | Механизм |
|---|------------|----------|
| 2.3.1 | Проверка прав через `tenant-core-app` | Сервис проверяет, является ли пользователь собственником или резидентом данного жилого комплекса |
| 2.3.2 | К партнёру передаётся только `device_id` и `user_id` | Минимизация ПДн |
| 2.3.3 | Rate limiting: 10 запросов/мин | Защита от DDoS |
| 2.3.4 | Все изменения прав логируются | Аудит |

## 3. Взаимодействие

### 3.1. Схема

```
Собственник открывает мобильное приложение
         ↓
Аутентификация через Keycloak (получение JWT-токена)
         ↓
Запрос на открытие домофона / шлагбаума
         ↓
API Gateway проверяет JWT-токен
         ↓
smart-home-integration-app:
   - проверяет, есть ли у пользователя доступ
   - получает данные из tenant-core-app
   - формирует запрос партнёру
         ↓
Партнёр "Умный дом" (внешняя система):
   - аутентифицирует сервис (OAuth2 + mTLS)
   - выполняет команду на устройстве
         ↓
Домофон открывается / Шлагбаум поднимается
```
### 3.2. API-контракты

**Открытие домофона:** `POST /api/v1/door/unlock`

```json
{
  "device_id": "door-12345",
  "timestamp": "2026-08-01T12:00:00Z",
  "method": "face_recognition"
}
```

**Открытие шлагбаума:** `POST /api/v1/barrier/open`

```json
{
  "device_id": "barrier-001",
  "vehicle_plate": "A123BC77",
  "timestamp": "2026-08-01T12:00:00Z"
}
```

**Ответ:**

```json
{
  "status": "success",
  "result": "unlocked"
}
```
