# Ролевая модель доступа к Kubernetes

## Группы пользователей и их роли

| Роль | Права роли | Группы пользователей |
|------|------------|----------------------|
| **cluster-admin** | Полный доступ ко всем ресурсам кластера (get, list, watch, create, update, patch, delete) | DevOps-инженеры, SRE |
| **developer** | Полный доступ к ресурсам в своих namespace: deployments, pods, services, configmaps, secrets (create, update, delete); доступ к ingress, pvc | Команды разработки (функциональные команды) |
| **operator** | get, list, watch для pods, services, deployments, statefulsets, configmaps, events, nodes; get, list, create для pods/log, pods/exec. **Без права изменять** | Инженеры по эксплуатации |
| **viewer** | Только просмотр ресурсов кластера: get, list, watch для pods, services, deployments, configmaps (без secrets) | Бизнес-аналитики |
| **auditor** | Просмотр всех ресурсов, включая secrets (get, list, watch) | Специалист по ИБ, внешние аудиторы |

## Обоснование

| Роль | Почему такие права |
|------|---------------------|
| **cluster-admin** | DevOps и SRE отвечают за инфраструктуру кластера — им нужен полный доступ для настройки, обновлений и устранения аварий |
| **developer** | Разработчики должны иметь возможность деплоить свои приложения, обновлять их и управлять конфигурациями в рамках своих namespace |
| **operator** | Инженеры эксплуатации следят за работой приложений — им нужен доступ к логам, exec и метрикам, но **не нужны права на изменение**, чтобы исключить случайные ошибки |
| **viewer** | Бизнес-аналитикам нужна информация о состоянии сервисов, но не нужны права на изменения или доступ к секретам |
| **auditor** | ИБ-специалист должен видеть все ресурсы включая секреты для проверок, но не должен иметь права изменять их |

## Принципы построения

1. **Минимальные привилегии** — каждой группе выдаётся ровно столько прав, сколько необходимо для работы
2. **Разделение обязанностей** — никто не имеет избыточных прав
3. **Namespace-изоляция** — разработчики и операторы ограничены своими namespace
4. **Аудит** — auditor имеет доступ ко всем ресурсам только на чтение
